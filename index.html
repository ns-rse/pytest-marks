Test Development

  • Don’t always want to run the whole test suite during development
  • May have a test that takes a long time e.g. test-slow
  • Run just test_slow1…
pytest tests/test_something.py::test_slow
  • Doesn’t exclude test_slow from the whole suite.
  • If test_slow takes a long time running whole suite delays feedback loop.
  • Solution - Create your own marks to select which tests are run

  1. Can dispatch individual tests from within Emacs using python-pytest 😉

Example - Test with @pytest.mark.*

import time
import pytest

@pytest.mark.slow
def test_slow() -> None:
    """A dummy test that takes a an hour to run."""
    time.sleep(60*60)
    pass

def test_quick() -> None:
    """A dummy test that takes 2 seconds to run."""
    time.sleep(2)
    pass

def test_very_fast() -> None:
    """A dummy test that takes 1 second to run."""
    time.sleep(1)
    pass

Configure via pyproject.toml

Let pytest know about the slow marks

[tool.pytest]
markers = [
  "slow: marks slow tests (deselect with '-m \"not slow\")",
]

Example - Selectively run tests based on marks

# Run just `test_slow` that is marked with 'slow'
pytest -v -m "slow"
# Run all other tests that are not marked 'slow'
pytest -v -m "not slow"

Configure permanently via pyproject.toml

Configure project to exclude slow tests by default.

[tool.pytest]
addopts = ["-m", "not slow"]
markers = [
  "slow: marks slow tests (deselect with '-m \"not slow\")",
]

Automatically add markers

  • Structured nomenclature of tests to indicates what the tests are doing allows automation of adding markers based on test names.
def test_func_function1():
    pass

def test_func_function2():
    pass

def test_exception_keyerror():
    with pytest.raises(KeyError):
        {"a": 0, "b": 1}["not a key"]

def test_exception_indexerror():
    with pytest.raises(IndexError):
        [0, 1, 2][3]

Configure via conftest.py

import pytest

def pytest_collection_modifyitems(items):
    for item in items:
        if "func" in item.nodeid:
            item.add_marker(
                pytest.mark.func
            )
        elif "exception" in item.nodeid:
            item.add_marker(
                pytest.mark.exception
            )
  • @pytest.mark.func added if test function includes func.
  • @pytest.mark.exception added if test function includes exception.

Update pyproject.toml

[tool.pytest]
  addopts = ["-m", "not slow"]
  markers = [
    "slow: marks slow tests (deselect with '-m \"not slow\")",
    "func: marks tests of functions (dselect with '-m \"not func\")"
    "exceptions: marks tests of exceptions (dselect with '-m \"not exceptions\")"
  ]

What marks are there?

  • Marks may grow over time.
  • Use pytest --markers to list.
  • Many extensions add @pytest.mark decorators
@pytest.mark.slow: marks slow testes (deselect with '-m "not slow")

@pytest.mark.syrupy_snapshot: test directly or indirectly uses the snapshot fixture

@pytest.mark.no_cover: disable coverage for this test.

@pytest.mark.mpl_image_compare: Compares matplotlib figures against a baseline image

@pytest.mark.filterwarnings(warning): add a warning filter to the given test. see https://docs.pytest.org/en/stable/how-to/capture-warnings.html#pytest-mark-filterwarnings

@pytest.mark.skip(reason=None): skip the given test function with an optional reason. Example: skip(reason="no way of currently testing this") skips the test.

@pytest.mark.skipif(condition, ..., *, reason=...): skip the given test function if any of the conditions evaluate to True. Example: skipif(sys.platform == 'win32') skips the test if we are on the win32 platform. See https://docs.pytest.org/en/stable/reference/reference.html#pytest-mark-skipif

@pytest.mark.xfail(condition, ..., *, reason=..., run=True, raises=None, strict=strict_xfail): mark the test function as an expected failure if any of the conditions evaluate to True. Optionally specify a reason for better reporting and run=False if you don't even want to execute the test function. If only specific exception(s) are expected, you can list them in raises, and if the test fails in other ways, it will be reported as a true failure. See https://docs.pytest.org/en/stable/reference/reference.html#pytest-mark-xfail

@pytest.mark.parametrize(argnames, argvalues): call a test function multiple times passing in different arguments in turn. argvalues generally needs to be a list of values if argnames specifies only one name or a list of tuples of values if argnames specifies multiple names. Example: @parametrize('arg1', [1,2]) would lead to two calls of the decorated test function, one with arg1=1 and another with arg1=2.see https://docs.pytest.org/en/stable/how-to/parametrize.html for more info and examples.

@pytest.mark.usefixtures(fixturename1, fixturename2, ...): mark tests as needing all of the specified fixtures. see https://docs.pytest.org/en/stable/explanation/fixtures.html#usefixtures

@pytest.mark.tryfirst: mark a hook implementation function such that the plugin machinery will try to call it first/as early as possible. DEPRECATED, use @pytest.hookimpl(tryfirst=True) instead.

@pytest.mark.trylast: mark a hook implementation function such that the plugin machinery will try to call it last/as late as possible. DEPRECATED, use @pytest.hookimpl(trylast=True) instead.

@pytest.mark.xdist_group: specify group for tests should run in same session.in relation to one another. Provided by pytest-xdist.

@pytest.mark.skip

  • Skip an individual test.
  • @pytest.mark.skip(reason="Don't like this test!")

Whole function

@pytest.mark.skip(
    reason="Don't like this test!"
)
def test_func_function1() -> None:
    pass

Individual paramterised sets

@pytest.mark.parameterise(
    ("string"),
    [
        pytest.param(
            "a",
            id="test1"
        ),
        pytest.param(
            2,
            id="test2",
            marks=pytest.mark.skip(
                reason="Don't like this test!"
            )
        ),
    ]
)
def test_func_function1(string: str) -> None:
    assert isinstance(string, str)

@pytest.mark.skipif

  • @pytest.mark.skipif(reason="Don't like this test!")
  • Useful if you now a test always fails on CI in a particular environment or Python version.

Whole function

import os
import platform

GITHUB_ACTIONS = os.getenv("GITHUB_ACTIONS") == "true"
OSX = platform.system() == "Darwin"

@pytest.mark.skipif(
    GITHUB_ACTIONS and OSX,
    reason="Test fails in CI on OSX!")
def test_func_function1() -> None:
    pass

Individual paramterised sets

Pytest testmon

  • Changes typically small
  • Only impact subset of tests
  • 🪄 Pytest testmon 🪄

a pytest plugin which selects and executes only tests you need to run. It does this by collecting dependencies between tests and all executed code (internally using Coverage.py) and comparing the dependencies against changes. testmon updates its database on each test execution, so it works independently of version control.

[dependency-groups]
tests = [
  ...
  "pytest-testmon"
  ...
]

As a pre-commit hook

  • On commits pytest --testmon run only on affected changes.
   - repo: local
     hooks:
       - id: pytest
         name: Pytest (testmon)
         entry: pytest --testmon
         language: system
         files: \.py$

Summary

  • Lots of different strategies for managing test suite!
  • Structured nomenclature of tests can be very useful.
  • Use any or many of these to speed up the feedback loop. 🪄
